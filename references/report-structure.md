# 报告结构与数据采集规范

## 数据采集与保真

- **来源优先级**：品牌官网产品页/规格页 > 官方新闻与资料页 > 官方旗舰店在售价格 > 权威第三方评测；经销商价仅作参考。
- **大页面抓取**：web_fetch 的 content 模式对产品页常因体积超限失败——改用 snippet 模式带 query 抽取，或直接用 general_search 找到规格页缓存片段。失败要如实换路径，不要编造数字填页。
- **未公布即「—」**：官方页面找不到的指标一律「—」，并在脚注注明「官方未公布该口径」。**禁止**用竞品同级别产品的数值推算、用宣传文案反推参数。
- **口径冲突要脚注**：同一产品不同官方页面口径不一致（如产品页 vs 官方对比表）时，两口径都列出并注明冲突位置，让读者自己判断。
- **来源清单**：报告末尾单列一章，逐条列出全部 URL 与检索日期；页脚写免责声明（内部参考、以官方最新公布为准）。

## 固定 7 章骨架

标题格式：`{我方产品} 竞争及定位分析报告`（不要用长对比句当标题）。吸顶导航锚点跳到这 7 章。

### 00 一页速览
- 三卡定位：我方深色卡 + 两张竞品白卡。每卡 = 角色标签（我方·定位/竞品一·定位）→ 产品名 → **一句话定位**（大白话，30 字左右）→ 官方叙事/关键参数段。
- KPI 条：**只放我方真正占优的指标**（4 个以内，网格 2→4 列）。我方弱势/竞品强项不进 KPI，挪到本段说明文字里，保持 KPI 的色彩语言（蓝=我方赢）纯净。
- 段末 caption：一句话点明双方强项分布 + 未公布口径用「—」。

### 01 产品概览
- 三卡等大展示框（统一高、`object-fit:contain` 居中），每卡：官方图 + 品牌名 + 一句话规格行 + 3-4 条核心参数短行。
- 产品图必须下载到 `assets/` 相对路径引用，补 `width/height + loading="lazy"`。

### 02 规格总对比表
- 宽表（min-width 760px）包在 `.table-scroll` 里，列顺序：参数 | 我方 | 竞品 A | 竞品 B。
- 按 6-8 组分类（如：成像/精度、产能/效率、自动化/智能化、材料生态、环境与散热、物理规格、连接与软件、价格），组标题行跨列浅色底。
- **我方列高亮**：浅蓝底（rgba(品牌,.07)）+ 表头 2px 品牌色下边框，形成从上到下的视觉轨。
- 窄屏右侧加渐隐滚动提示；未公布 = 「—」；口径冲突脚注紧跟表下。

### 03 关键指标图表（4 张 ECharts 柱图）
- 每张：图卡 = 标题 + 副标题口径 + 图 + 一句解读（chart-read）。
- 选 4 个最能说明立场的指标（示例：产能、精度、寿命、价格）。柱状图**零基线**。
- **反向指标**（数值越低越好，如像素、故障率）必须在标题右侧加「越低越好」胶囊，防止扫读误判。
- ECharts 走 jsDelivr CDN，必须保留加载失败的文字降级分支（「数据见第 02 章表格」）；打印时隐藏 canvas、显示预写好的数据文字。

### 04 核心差异化卖点（专属模块一）
- 6 张左右卖点卡：编号 + 标题 + 3-4 句解释 + **证据行**（官方标称数字/认证/来源编号）+ **竞品对照行**（竞品 A/竞品 B 各自在该点上是什么状态，一句话）。
- 每条卖点都必须能回答「竞品在哪一点上给不出这个」——给不出的写「官方未公布」，不要写贬损话。

### 05 目标客户与目标场景（专属模块二）
- 5 类优势客户行：客户类型 → 核心诉求 → 我方优势（对应 04 章卖点编号）→ 一句话结论（≤35 字）。
- 场景适配表：8 个典型场景 × 三方产品，用 ✓✓/✓/△/✕ 标注适配度，依据来自前文数据。
- **诚实让位框**（必须有）：什么情况下应该主动让给竞品——例如竞品的幅面/价格更适合纯模型创作用户。这一框是报告可信度的关键。

### 06 结论与销售建议
- 按每个竞品两段：竞品优势（如实写）+ 我方对位优势（对应卖点编号）。
- 3-5 条可执行建议（优先跟进谁、什么话术锚点、被质疑数据时怎么回溯）。

### 07 数据来源与免责
- 全部 URL 列表 + 检索日期 + 免责说明。

## 版式节奏
- 章节白底/灰白（#F5F5F7）交替；每章 section 垂直居中标题 + sec-lead 一句引导。
- 移动端单列优先；桌面 ≥820px 才切多列。
